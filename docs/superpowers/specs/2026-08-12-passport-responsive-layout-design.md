# 여권 반응형 레이아웃 보정 설계

## 1. 목표

`/boarding-pass/passport`의 열린 여권이 모바일, 태블릿, 데스크톱 휴대폰 셸에서 텍스트나 주요 정보가 잘리지 않도록 한다. Figma의 390px 모바일 구도와 기존 Three.js 페이지 전환은 유지한다.

## 2. 원인

열린 여권은 507px 고정 폭이지만 왼쪽 위치를 `margin-left: 12vw`로 계산한다. `vw`는 여권 stage나 390px 휴대폰 셸이 아닌 브라우저 전체 폭을 기준으로 한다.

- 390px 모바일: 46.8px로 Figma 구도와 일치한다.
- 768~1199px 태블릿: 폭이 커질수록 여권이 중앙에서 벗어난다.
- 1200px 이상 데스크톱: 휴대폰 화면은 390px로 고정되지만 여권 여백은 전체 브라우저 폭에 따라 증가해 프로필 텍스트가 잘린다.

Three.js CSS3DRenderer는 현재 DOM 좌표를 시각적으로 변환할 뿐 정지 상태 배치를 결정하지 않으므로 수정 대상이 아니다.

## 3. 배치 규칙

기존 507×394px 열린 여권 크기와 stage의 clipping은 유지하고 위치 계산만 교정한다.

- 320~767px: 기존 `12vw`를 유지해 390px Figma 구도와 좁은 모바일 대응을 보존한다.
- 768~1199px: 열린 여권에 `margin-inline: auto`를 적용해 태블릿 본문 중앙에 507px 전체를 표시한다.
- 1200px 이상: 390px 휴대폰 화면의 12%인 `46.8px`을 고정값으로 사용한다. 휴대폰 셸 안에서 모바일과 같은 상대 위치와 의도적 오른쪽 페이지 clipping을 재현하되, 왼쪽 프로필 정보는 모두 보이게 한다.

전체 애플리케이션의 태블릿 셸 정책, `MobileShell`, safe area, 여권 자산 크기와 DOM 구조는 변경하지 않는다.

## 4. 구현 범위

수정 대상은 `PassportPage.module.scss`의 열린 여권 위치 규칙과 해당 회귀 검증으로 제한한다.

- 새 의존성, 새 반응형 유틸리티, JavaScript viewport 분기는 추가하지 않는다.
- Three.js 카메라, pivot, 스와이프 임계값과 애니메이션은 변경하지 않는다.
- 표지와 여행 기록 바텀시트는 변경하지 않는다.

## 5. 검증

자동 테스트는 열린 여권의 기존 크기와 새 breakpoint별 위치 계약을 고정한다. 실제 레이아웃은 Edge 브라우저에서 다음 기준으로 검증한다.

- 320, 390, 430px: 기존 모바일 구도와 가로 overflow 유지
- 768, 1024, 1152px: 507px 열린 여권 전체 노출, 화면 중심 오차 2px 이하
- 1200, 1440px: 휴대폰 화면 기준 여권 왼쪽 약 66.8px, 프로필 오른쪽이 화면 안쪽에 위치
- Three.js renderer 준비 상태와 reduced-motion fallback 모두 동일한 CSS 위치 규칙 적용
- 전체 `npm run verify` 통과

## 6. 완료 조건

- 모바일 Figma 구도가 바뀌지 않는다.
- 태블릿에서 열린 여권이 한쪽으로 치우치거나 잘리지 않는다.
- 데스크톱 휴대폰 셸에서 프로필·국적·이름·발급일·크레딧과 제품 CTA가 잘리지 않는다.
- 기존 화살표, 스와이프, 진행률과 시트 동작에 회귀가 없다.
