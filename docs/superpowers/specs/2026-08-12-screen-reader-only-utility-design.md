# 화면 읽기 전용 텍스트 숨김 복구 설계

## 1. 목표

상품 목록·상품 상세 등에서 접근성용 `h1`, `h2`, 상태 문구가 화면에 노출되는 문제를 해결한다. 의미 있는 제목 구조와 스크린 리더 접근성은 유지한다.

## 2. 원인

화면 읽기 전용 요소는 Tailwind의 `sr-only` 클래스를 사용한다. 현재 새 개발 서버에서도 생성된 CSS에 `.sr-only`을 포함한 utilities가 없고 원시 `@tailwind utilities`가 남는다. 따라서 클래스가 아무 스타일도 적용하지 못해 일반 제목처럼 표시된다.

`89f0f15`에서 각 CSS Module의 정상 동작하던 `visuallyHidden`을 공통 `sr-only`로 교체한 뒤 이 문제가 노출됐다.

## 3. 선택안

### 권장: 전역 네이티브 `.sr-only`

`globals.scss`에 표준 화면 읽기 전용 스타일을 한 번 정의한다.

- 현재 모든 `className="sr-only"` 사용처를 동시에 복구한다.
- JSX, 페이지별 CSS Module과 의존성을 변경하지 않는다.
- Tailwind 처리 여부와 관계없이 동작한다.

### 제외: 페이지별 `visuallyHidden` 복원

같은 선언을 여러 CSS Module에 다시 만들게 되어 중복이 생기므로 제외한다.

### 후속: Tailwind 전체 파이프라인 교정

현재 다른 Tailwind utilities도 생성되지 않는다. 이를 전면 교정하면 NotFound 등 다른 화면의 스타일에도 영향을 주므로 이번 두 화면의 숨김 제목 복구와 분리한다.

## 4. 구현 범위

- `src/styles/globals.scss`에 `.sr-only` 전역 스타일 추가
- 상품 목록·상세에서 숨김 제목은 DOM에 유지
- `section[aria-labelledby]`, `aria-live` 연결 유지
- 새 의존성 및 페이지별 예외 추가 없음

## 5. 검증

- 상품 목록의 `상품 목록` h1과 컬렉션 h2가 접근성 트리에는 존재하고 시각적으로 1×1px 영역에 숨겨지는지 확인한다.
- 상품 상세의 `상품 상세` h1과 장바구니 상태 문구가 같은 계약을 따르는지 확인한다.
- 존재하지 않는 상품의 오류 화면 h1은 `sr-only`가 아니므로 계속 보이는지 확인한다.
- 실제 Edge 브라우저에서 상품 목록과 정상 상품 상세에 숨김 제목이 노출되지 않는지 확인한다.
- 전체 `npm run verify`를 실행한다.

## 6. 완료 조건

- 화면에서 중복된 `상품 목록`, `상품 상세`, `Autumn Winter 2026` 숨김 제목이 보이지 않는다.
- 각 페이지의 의미 있는 heading 구조와 스크린 리더 이름은 유지된다.
- 다른 화면의 기존 `sr-only` 요소도 같은 전역 규칙을 사용한다.
